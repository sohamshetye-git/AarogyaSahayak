DESIGN A COMPLETE, PRODUCTION-QUALITY, RESPONSIVE UI/UX IN FIGMA FOR:

AAROGYA SAHAYAK – ASHA COPILOT

A responsive field-healthcare portal for ASHA workers in rural India.

IMPORTANT PRODUCT CONTEXT

Aarogya Sahayak is a voice-first rural healthcare assistance ecosystem connecting:

* Rural citizens
* ASHA workers
* PHC doctors
* District health officers
* Government health systems

This design is specifically for the ASHA WORKER interface.

Do not design the citizen application in this file.

The citizen uses a separate, simplified React Native voice application. When the citizen reports symptoms or an offline risk is detected, a case is sent to the ASHA Copilot interface.

The ASHA interface helps the worker:

1. View prioritized citizen alerts.
2. Acknowledge urgent cases.
3. Call citizens and schedule home visits.
4. Record symptoms and vital signs.
5. Verify AI-extracted information.
6. Conduct consent-based voice-assisted field visits.
7. Work during limited or unavailable internet.
8. Refer high-risk cases to a PHC.
9. Assist citizens with health schemes.
10. Generate and send structured referral reports.
11. Track doctor acknowledgement.
12. Schedule and complete follow-ups.

The interface must never present AI as a doctor.

AI output must always be labelled:

“AI-assisted summary – please verify.”

Do not display definitive diagnoses.

Use language such as:

* Warning signs detected
* Urgent professional evaluation recommended
* AI-assisted information
* Please verify
* Potentially relevant scheme
* Final eligibility verification pending

Do not display:

* You have pre-eclampsia
* AI diagnosis
* Confirmed disease
* 97% disease probability
* Internal chain-of-thought
* LLM, RAG, Gemini, Neo4j or API terminology in the worker-facing interface

2. DESIGN PRINCIPLES
====================

The interface must feel:

* Trustworthy
* Calm
* Professional
* Human
* Government-health oriented
* Accessible
* Practical
* Field-ready
* Modern but not futuristic
* Suitable for rural India
* Optimized for intermittent connectivity

Avoid:

* Glassmorphism
* Excessive gradients
* Neon colours
* Gaming-style UI
* Social-media appearance
* Corporate fintech appearance
* Excessive shadows
* Tiny controls
* Overly dense hospital-management layouts
* Decorative charts without operational value
* Complex medical jargon
* Long paragraphs
* Excessive animation

PRIMARY UX PRINCIPLE:

“SEE PRIORITY → CONTACT CITIZEN → CONDUCT VISIT → VERIFY → REFER → FOLLOW UP”

The dashboard must immediately answer:

“What should I do first today?”

7. ACCESSIBILITY REQUIREMENTS
=============================

Meet WCAG 2.2 AA contrast requirements.

Design for:

* ASHA workers using low-cost Android phones
* Outdoor sunlight
* Limited digital familiarity
* Multilingual use
* One-handed use
* Limited connectivity
* Elderly ASHA workers
* Screen-reader users

Requirements:

* Minimum touch target: 48 × 48 px
* Visible keyboard focus states
* Strong colour contrast
* Screen-reader labels
* Dynamic font scaling
* Logical reading order
* Form labels above fields
* Do not use placeholder text as the only label
* Error message beside the relevant field
* Icon + label for every important action
* Do not use swipe-only actions
* Provide alternatives to voice input
* Allow reduced-motion mode
* Keep warning messages calm and actionable
* Avoid flashing animations
* Never make an urgent action depend only on colour
